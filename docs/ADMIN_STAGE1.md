# 管理员规则与清单维护：第一阶段

本模块按 v3 契约实现 AD01—AD06，供本地独立自测和后续 A/B/C/D 联调。业务使用现有 `sys_admin`、`sys_admin_delegable_role`，无需数据库迁移。用户、部门和角色由 Mapper 读取，本模块不会写入这些模块的业务表。

## 已实现接口

| 接口 | 功能/功能权限 |
|---|---|
| `GET /api/v1/admins` | 管理范围内的有效/撤销任命；`IAM_ADMINS_VIEW` |
| `POST /api/v1/admins/appointments` | 任命同级或下级管理员；`IAM_ADMINS_WRITE` |
| `POST /api/v1/admins/{userId}/revoke` | 撤销任命，允许同根同级互撤及自撤；`IAM_ADMINS_WRITE` |
| `GET /api/v1/admins/me/scope` | 本人任命状态、管理根、清单版本；`IAM_ADMINS_VIEW` |
| `GET /api/v1/admins/{userId}/delegable-roles` | 本人或管理上级读取清单；`IAM_GRANTS_VIEW` |
| `PUT /api/v1/admins/{userId}/delegable-roles` | 上级全量替换下级清单；`IAM_GRANTS_DELEGATE` |

响应沿用 `ApiResponse`。ID 必须为正整数十进制字符串；管理员等级必须为 JSON 整数（1—65535）；原因不能为空且最多 512 字符。分页默认 1/20、最大 500。清单允许空集合，不允许重复 ID；版本为 `vN`，版本不符返回 `409 VERSION_CONFLICT`。数值 ID、字符串/小数等级等不进行隐式类型转换。

列表先按管理范围过滤，再分页；可选 `deptId` 筛选该部门及子树。详情或修改目标不存在、目标不在可见范围时返回 `404 RESOURCE_NOT_FOUND`。资格、等级和角色委派错误使用已有业务码。数据库连接在开启事务时失败也返回 `503 AUTH_STATE_UNAVAILABLE`。

## 规则与本地临时口径

- 一级管理员管理集团范围；其他等级按任命部门及 `parent_id` 子树判断，不依赖字符串前缀或组织树深度。缺失/循环组织关系拒绝处理。暂停、离职、冻结链和撤销任命不能继续执行管理操作。
- 任命同时检查目标用户在操作者范围内，以及新管理根和等级是否合法；不额外要求目标用户必须属于所选的新管理根。有效任命重复创建返回 `409 DUPLICATE_RESOURCE`，不借此修改已有范围。
- 撤销只改变任命状态；再次撤销已撤销目标按已完成返回。保留本人清单、本人管理功能角色及此前授予其他用户的角色。重新任命已撤销管理员时清空旧清单、递增版本，并收缩相关下级清单。
- 清单配置限严格上级（等级数字更小）且部门范围包含目标，不允许同级或本人修改自己的清单。一级可委派启用的业务角色，其他管理员还必须拥有该清单项。超级角色始终禁止；管理角色细分等级规则未确定，默认拒绝，等待 `ManagementRoles` 接入。
- 清单缩减暂以每项 `configured_by` 追踪委派来源，按角色逐层移除受影响项；每个受影响管理员每次请求只递增一次版本。其他配置者的其他记录保留，不改变既有用户授权。该表每个管理员/角色只保存一个当前配置者，不支持同一项多来源委派。
- `configured_by=NULL` 的预置项、外部写入的未知委派关系、组织调整后的重新审批、管理角色等级映射及超级用户受控初始化/恢复尚未完成业务确认，不在本次完整验收结论内。递归收缩验收针对本模块建立的可追踪链。

## 事务与协作入口

`AdminService` 负责事务和编排，`AdminRules` 负责规则，`AdminMapper`/XML 负责 SQL。全量清单替换、下级收缩、版本递增、签名接入和审计接入在同一事务内执行；任何异常回滚。空清单也经过签名接入点。

第一阶段为保证委派链修改的正确性，M5 写操作固定顺序锁定管理员、部门、角色、清单，再按用户 ID 锁定相关用户；使用当前读复核，暂时串行化管理员写操作。查询不使用跨请求缓存。该实现尚未进行大规模性能验收，后续若缩小锁范围，必须保留并发回归用例。

`AdminPolicyService` 提供 `requireAdministrator`、`requireLevelOne`、`requireUserScope`、`requireDepartmentScope`、`requireDelegableRole`，供 A/B/C 的写 Service 复用。要求调用方已有事务（`MANDATORY`），并传入经验证的操作者 ID；调用方仍需执行 M6 功能检查。跨模块联调时需统一锁顺序，避免先锁用户再调用本模块造成锁顺序相反。

`AdminPorts` 定义暂定的内部 Java 接入点，不新增内部 HTTP 接口：

| 接入点 | 责任与要求 |
|---|---|
| `Identity` | 从真实认证上下文取得当前用户，不信任请求中声明的操作者 ID |
| `Functions` | 检查当前功能权限、真实会话等；写事务内复核当前状态 |
| `Integrity` | 读取完整规范字段验签；对变更管理员及其清单（含空集合）签名，与业务同事务 |
| `Audit` | 保存原因及变更证据，与业务同事务；失败抛出业务异常 |
| `ManagementRoles` | 管理角色的等级/任命资格政策，当前默认拒绝 |

`AdminData`/`AdminState` 是规则判断所需的最小投影，不是签名序列化格式。签名适配器必须按其中对象 ID 读取并验证完整规范字段，不能直接给这些投影签名。`Change` 提供本次原因、操作人、目标、前后状态和受影响管理员 ID，供审计适配器取证。

当前生产默认适配器明确拒绝：未接入身份返回 `INVALID_TOKEN`，功能权限缺失返回 `AUTH_STATE_UNAVAILABLE`，签名/审计缺失返回相应 503。实际 Bean 接入后替换默认 Bean。没有测试身份请求头、开发免鉴权开关或默认超级账号。

真实 JWT、M6 功能鉴权、密码/签名算法、完整审计及拒绝日志仍由相应模块接入。本次只验证这些依赖的调用边界、拒绝行为和事务保障，不宣称完成整条安全链路。

## 自动测试

在后端仓库目录运行：

```powershell
.\mvnw.cmd test
.\mvnw.cmd verify -Pintegration-tests
```

第一条运行规则、服务、共享校验、HTTP 契约和默认拒绝测试，不需要 Docker。第二条还运行 `AdminIT`：需要 Docker Desktop，首次下载依赖及镜像。Docker 不可用会明确失败，不静默跳过集成测试。

集成测试使用与 Compose 相同摘要的 MySQL 8 镜像，通过镜像初始化入口执行原建表脚本（含 `DELIMITER` 和触发器）。随机端口、临时容器、独立数据库参数由 Testcontainers 提供，数据放在临时文件系统，测试结束自动清理；不读取个人数据库密码或连接已有开发库。所有测试身份、签名替身和审计故障注入均只在 `src/test` 中。

测试数据只在临时库中建立，不提供可用的业务登录凭据。测试重点包括范围过滤、自撤、递归收缩、历史授权保留、版本冲突、事务失败回滚、并发资格复核及共享检查入口的事务约束。
