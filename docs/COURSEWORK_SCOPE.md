| 项目 | 当前范围 |
| --- | --- |
| 鉴权日志 | 保存用户、应用/API、方法/模板、是否允许、原因、时间、requestId 和 decisionId；取消完整决策事实快照及 permissionVersion 摘要。保留权限数据验签和基础日志封印。管理变更日志仍保留授权历史所需信息。 |
| HR/OA 事件 | 保留事件编号去重、同号异内容冲突、业务版本检查；登记事件、修改业务、保存成功结果在同一事务。失败整体回滚，返回明确错误。取消在线恢复和独立失败记录状态机；网络结果不确定时先核对数据库，不能盲目重复执行。 |
| 管理员清单 | 仅一级管理员为范围内较低等级管理员直接配置清单；其他管理员可以在自己清单内授予用户角色，不能继续转委派。替换只影响目标清单，没有递归收缩。旧版非一级配置的委派记录不再提供可授权资格。 |
| 批量操作 | 每次 1–100 位用户，同步执行，每人独立事务，HTTP 200 返回全部逐项结果。无后台任务、自动重试、轮询和重启恢复；删除 GR06 查询接口。不再依赖请求幂等键；授予仍按稳定 sourceRef 去重，回收指定来源可重复确认。 |
| 组织变化 | 仅离职和管理员本人部门变化自动撤销任命并清空本人清单。组织新增人员/部门、子树调整不自动撤销其他管理员；管理范围按当前组织树计算。合并等其他变化由一级管理员手工确认，已合并部门的失效管理根仍会被正常范围检查拒绝。 |
| 验收与运维 | 使用课堂规模数据演示登录、授权、鉴权、回收及异常；记录实际耗时，不设万人集中登录或 20/50ms 硬指标。不做每周全量、每日增量调度，仅提供手动备份与恢复步骤。 |

账号与密码规则、角色及授权来源、部门冻结、用户会话失效、功能权限与管理范围双重校验、数据签名、服务请求签名及防重放继续保留。数据库旧批量表暂时保留作历史兼容，不自动清库，不再用于新请求。开发测试仍可模拟 HR/OA 和短信。

## 课堂演示验收

1. 登录并取得 JWT；无效令牌拒绝。
2. 新建应用、权限单元与 API，关联角色并授予用户；鉴权允许。
3. 回收最后一条有效来源后，再次鉴权拒绝；仍有其他来源时角色保留。
4. 一级管理员直接配置下级可授权清单，二级管理员转委派返回拒绝。
5. 批量请求同时包含合法与范围外目标，逐人返回成功/失败；101 人请求被拒绝。
6. 同一成功 HR/OA 事件重发只返回原结果，同号不同内容拒绝；业务失败不留下半完成修改。
7. 普通人员调入不撤销接收部门管理员；管理员本人调岗和离职撤销本人任命。
8. 冻结部门影响业务权限，解冻后按现有授权恢复。签名被篡改仍拒绝。

## 手动备份与恢复

演示前停止写入，用 MySQL 的 mysqldump 对 unified_permission 做一次完整导出，密码通过交互输入；备份文件放在仓库外。恢复时先将导出文件导入一个单独的演示数据库，再修改本地连接配置、验证登录和权限结果。保留本地签名密钥，避免恢复后无法验证原签名。不要直接覆盖唯一的现有数据库。
