# C2-03 HR Collaboration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** C 精确回收岗位来源、清理离职资格并检查复职，与 A 人员、D 签名审计、事件结果同事务。

**Architecture:** 在 A 事件锁之后先调用 C 准备阶段，沿用管理员→部门→角色→清单→全用户→资源锁。HR 专用参与者不依赖人工管理员资格；来源与关系一致性先验签检查，C 签 USER_GRANTS，A 最终签 USER_IDENTITY，提交前验证完成事实。

**Tech Stack:** Java 21 / Spring Boot / MyBatis / MySQL 8.0.46 / Testcontainers / JUnit 5。

**Spec:** [总计划第五节](2026-10-18-c-stage2.md)、[现有交接](../../C_STAGE2_HANDOFF.md)、`service/hr/HrCollaboration.java`。

## Global Constraints

- 使用既有三层架构，不增加 DAO、Redis、内部 HTTP 接口或第二套事件框架。
- 不伪造管理员执行 HR/OA，不把 `TrustedEventContext` 的构造本身当作认证成功。
- 业务事实、签名、关键审计与相应成功结果必须原子提交。
- 不改写历史授权来满足现时规则，不自动恢复已撤销来源，不因验签失败给旧数据自动补签。
- 管理角色规则仍默认拒绝；不引入新表、字段、HTTP、事件认领或恢复机制。
- 现有 C2-01/02 工作区及证据保留，顺序执行，不自动提交/推送。
