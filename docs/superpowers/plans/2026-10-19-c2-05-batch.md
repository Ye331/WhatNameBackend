# C2-05 Batch Recovery Implementation Plan

> **For agentic workers:** Execute this plan task-by-task in the current session. The user requested implementation; preserve the existing C2-01–04 work and do not start parallel agents.

**Goal:** Safely resume persisted GR03 tasks, bound database retries, and verify current authority on every item and attempt.

**Architecture:** Keep the existing item transactions and GR06. A separate task guard transaction locks the batch row with NOWAIT across execution; each reservation and each business attempt uses REQUIRES_NEW. Existing attempts records reservations before execution, so process death consumes the reserved attempt. Recovery scans use keyset pagination and a bounded local dispatch set; database locks protect across processes.

**Tech Stack:** Java 21, Spring Boot, MyBatis, MySQL 8, JUnit, Testcontainers.

**Spec:** [Stage plan, C2-05](2026-10-18-c-stage2.md), [handoff](../../C_STAGE2_HANDOFF.md).

## Global Constraints

- 使用既有三层架构，不增加 DAO、Redis、内部 HTTP 接口或第二套事件框架。
- 不使用跨请求允许缓存；等待锁结束后必须复核当前事实，不能把旧快照当成最新权限。
- 业务事实、签名、关键审计与相应成功结果必须原子提交。
- No schema or external API changes. APPLIED and FAILED are terminal. dryRun=true stays INVALID_ARGUMENT (optional enhancement deferred).
- Retry only classified transient database failures, at most three retries after the initial attempt (four persisted reservations). Unknown/nonretryable errors become FAILED only after a separate locked state check confirms PENDING; infrastructure preventing that check leaves recoverable work without asserting failure.
