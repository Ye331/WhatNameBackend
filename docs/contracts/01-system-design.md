# 统一权限管理系统——课程作业设计说明

版本：v4，2026-10-23。当前范围见 [课程作业简化范围](../COURSEWORK_SCOPE.md)，它取代旧版 v3.1 的复杂恢复、递归委派、后台批量任务和生产性能运维指标。旧版已提交留档，原需求 PDF 不作覆盖修改。

## 1. 工程结构

一个 Spring Boot 工程，Java 21、Spring Data JPA、MySQL 8，Controller → Service → Repository。前端为 Vue。当前不用 Redis、消息队列或微服务。姓名、手机号使用虚构明文演示值；密码仅保存带盐哈希。权限和手机号防篡改签名保留。

## 2. 六模块分工

M1 账号与登录、M2 组织与HR、M3 资源、M4 角色与授权、M5 管理员与范围、M6 在线鉴权。每个模块以API为入口学习和验收。签名、审计和事务为公共支撑。

## 3. M1 账号与登录

正式及外包员工从 HR 工号同步；临时账号由管理员在范围内创建。用户名重名追加 SG 后六位，临时用户名由服务生成。登录支持用户名密码、手机号密码；短信验证码仅支持首次设密和重置密码。账号状态为可用、暂停、离职，账号不物理删除。保留密码规则、失败锁定、验证码限流与一次性消费。

JWT 表示身份，会话版本变化使旧令牌失效，注销仅撤销当前 jti。令牌不缓存角色权限。临时账号的暂停/恢复可人工操作，HR 人员状态由 HR 同步维护。

## 4. M2 组织和 HR

组织使用部门树，防止循环。HR 支持部门同步、员工同步、调岗、离职和合并。请求必须通过 HR 服务签名及能力检查。

- 调岗：回收旧部门 DEPT_POSITION 来源，保留其他来源，移动部门；新权限由人手授予。
- 离职：回收全部来源、状态变离职、会话版本加一，撤销本人管理员任命。
- 合并：移动人员和直属下级，保留人员角色，原部门标记合并去向。
- 冻结：只改部门状态；鉴权检查祖先链，影响下级业务权限；不阻止登录，不删授权。
- 自动任命复核仅处理离职、管理员本人调岗；其他组织范围变化由一级管理员手工确认。

事件以来源和 eventId 唯一标识，同编号异内容报 409，已成功事件返回原结果，HR 对象版本必须递增。事件登记、业务变化和成功结果同事务提交；失败整体回滚。不提供在线恢复入口、不保存新 PENDING_RECOVERY 状态、不对故障自动接管。旧版非终态事件需人工核对，禁止直接接管。

## 5. M3 应用权限资源

维护应用、目录/权限单元、API 和菜单 API 关联。目录组织层级，type=2 权限单元用于授权。API 按 HTTP 方法与规范化路由模板登记，拒绝歧义路由。关联限于同应用。PATCH 只修改已给出的字段；关联 PUT 全量替换，使用查询返回的 vN 版本防止覆盖。

资源读取需要管理读取资格与 IAM_RESOURCES_VIEW；写入需要一级管理员及 IAM_RESOURCES_WRITE。本系统 IAM 应用不能被停用。变更后更新相关签名及审计。

## 6. M4 角色与授权

RBAC0：用户 → 角色 → 权限单元 → API。多角色取并集，不做角色继承、显式禁止、自动过期或职责分离。角色定义、角色菜单写入仅一级管理员可操作；普通接口不能创建或修改超级角色。角色菜单也采用全量替换和版本控制。

用户授权记录 MANUAL、DEPT_POSITION、OA_APPROVAL 等独立来源；回收针对来源，剩余有效来源为零才移除有效角色。单人 HTTP 授予/回收 expectedVersion 必填；内部批量/HR/OA 走受控业务入口，不强制客户端版本。保留授权历史。

批量接口同步处理最多 100 人，每人独立事务并复核当前权限、管理范围、角色清单。返回全部逐人结果及成功/失败数。业务拒绝允许部分成功；基础设施故障返回错误，先查询实际授权状态再决定下一步。不创建持久任务、不自动重试、不提供任务查询与重启恢复。Idempotency-Key 不再作为批量请求去重依据；稳定授权来源键仍防止重复授予。

OA 接口仅执行已批准的角色授予/回收，不实现审批引擎。校验可信服务、操作/角色/部门范围，复用简单事件去重及同事务处理。

## 7. M5 管理员与范围

功能权限和管理员任命相互独立；执行管理动作需要同时通过两者。一级管理员覆盖全公司，其他等级按任命部门及当前下级树确定范围；等级数值越小权限级别越高。保留任命、撤销、范围读取及普通角色可授权检查。

可授权清单只由一级管理员直接配置给较低等级管理员。二级及以下可以使用清单给用户授予角色，不能继续配置别人的清单。替换仅更新目标，没有递归传播。旧版由非一级管理员配置的条目不再提供可授权资格。任命撤销后失去管理资格，不删除账号或业务角色；本人调岗/离职清空本人清单。

组织新增人员/部门及子树变化不自动撤销接收部门管理员。已合并或冻结的管理根继续按有效性检查拒绝操作，待一级管理员手工确认和重新任命。

## 8. M6 在线鉴权

业务后端携带用户 JWT 和可信业务服务签名调用 auth/check，应用 ID 来自已验证服务身份。每次在独立数据库事务读取当前用户、会话、组织、角色来源、菜单及 API，保留必要验签。仅 allowed=true 可放行。撤权提交后开始的新鉴权读取新状态。

auth/menus 返回本人应用菜单及任命摘要；users/{userId}/permissions 供有范围资格的管理员查看目标菜单。目录仅导航，不直接构成 API 权限。

鉴权记录只保存用户、应用/API、方法/模板、允许与原因、时间、requestId、decisionId。取消完整角色/组织/签名事实快照及 permissionVersion。管理变更日志保留授权历史需要的变更信息；日志封印与数据防篡改签名继续保留。审计写入失败不返回允许。

## 9. 事务和安全

管理写入在同一事务更新事实、签名与审计；维持现有锁顺序和必要版本控制，不因简化而绕过授权。外部事件同事务提交登记和业务，批量逐人独立提交。数据库、可信权限状态或签名故障时拒绝放行。

保留 JWT 校验、密码哈希、验证码 HMAC、Ed25519 数据及服务请求签名。服务请求使用 clientId/keyId/时间戳/nonce/签名头，防止伪造和重放。签名失败不得自行重签后放行。超级用户保留受控初始化及紧急恢复通道，与已取消的 HR/OA 在线事件恢复无关。

## 10. 数据和验收

保留现有数据库表及历史记录，不自动删除旧批量表。新批量操作不再写入 sys_grant_batch、sys_grant_batch_item。修改数据库前先备份，已有库不自动重建。

课堂演示使用少量部门、用户和两个示例应用，验证完整授权回收链路及越权、重复事件、部分失败、冻结、旧令牌、篡改拒绝。记录实测耗时，不设一万人集中登录或 20ms/50ms 硬指标。不建设备份调度，使用手动完整备份和独立库恢复验证，步骤见当前范围文档。
