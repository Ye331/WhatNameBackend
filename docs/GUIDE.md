# 启动、演示与学习

运行步骤见 [后端 README](../README.md)，业务规则见 [功能范围](FUNCTIONAL_SCOPE.md)。

## 全量数据

三份来源文件统一位于工作区 data/。prepare-data.py 仅使用 Python 标准库，读取全部实际行、展开合并单元格、检查表头及重复标识，不连接数据库。

当前来源为 111 个部门、10,000 名员工、18 个来源应用、359 条功能记录。初始化导入全部基础记录，并增加 IAM 与 OA、HR 两个演示应用，共 21 个应用。来源功能矩阵只作参考资源导入，不把“查看/审批”等文字推断为实际授权。

来源功能生成参考 API 模板，不代表已经实现这 18 套外部业务。可直接运行的演示为 OA/HR 各四个功能。IAM 自身的 14 个菜单权限对应真实管理接口。

全量员工没有公开默认密码：初始化写入未知随机密码哈希，需由有权限的管理者为选定演示员工重置密码。不会生成包含全员密码的文件。

## 推荐演示流程

1. 初始化管理账号登录，展示全量员工、部门及应用资源。
2. 创建临时账号，分配“演示业务角色”。
3. 用另一个浏览器会话登录临时账号，在业务演示页面操作 OA/HR。
4. 管理账号回收临时账号角色；临时账号不重新登录，点击旧菜单应被后端拒绝。
5. 创建业务管理员角色，只配置用户查看和授权相关菜单，分配给部门员工，展示相同页面及不同数据范围。
6. 使用 system.http 调用 HR 调岗、离职和 OA 授予/回收。
7. 在独立演示库修改手机号或关联表，不修改签名，展示拒绝。完成后恢复原值，不能通过自动重签掩盖篡改。
8. 演示管理员回收自己的权限，再用本地 recover 恢复。

## 常见问题

- 角色配置页面中的“配置权限”需要角色权限配置和资源查看权限，才能选择菜单。
- 权限分配页面需要 IAM_GRANTS_VIEW；保存需要 IAM_GRANTS_WRITE。不需要另行任命管理员。
- ALL 不是超级用户开关，只是数据范围；每个操作仍需 IAM 菜单权限。
- 冻结本人部门也会阻止本人管理权限，应使用范围外有权限的账号解冻，或在独立演示环境从有效备份恢复。
- recover 恢复受控初始化账号的管理角色和密码，不自动修复篡改数据或冻结组织。
- 改密、重置密码和注销均使该账号旧会话失效，需要重新登录。
- 旧库不能直接用于新代码，启动时会检查结构。旧配置保留，新配置 application-coursework.yml 后加载覆盖连接。

## 备份

数据库使用手动完整备份，密钥文件独立保管。恢复到另一数据库，核对数据及对应签名密钥后再连接。不自动恢复，不删除篡改现场。
