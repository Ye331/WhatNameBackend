## 运行

在 backend 中使用 Java 21：

```powershell
.\scripts\dev.ps1 test
.\scripts\dev.ps1 test -FullImport
.\scripts\dev.ps1 test -FullImport -Integration
```

脚本先 clean，再按需整理全量来源文件，最后 verify。默认运行完全自包含的小型数据夹具；全量来源导入是显式选择的额外测试。原 Python 测试不再由此入口运行。直接使用 Maven 时执行 `./mvnw.cmd clean verify -Pcoverage`。

## 新测试范围

| 测试类 | 验证内容 |
|---|---|
| SimplifiedBusinessTest | 真实 Spring HTTP、业务服务、JPA 与签名；每个场景清空独立测试库并重新初始化 |
| SimplifiedInputTest | ID、密码、手机号、HR 登录名、集合输入、路由模板与冲突边界 |
| SimplifiedSessionTest | 令牌有效期、签发方/受众、签名、会话版本、错误输入与密码哈希 |
| SimplifiedConfigurationTest | 密钥生成/重启/损坏、显式配置、服务凭据、初始化命令分发与旧库结构拒绝 |
| SimplifiedMySqlIT | 新业务套件运行于独立 MySQL 容器；不继承旧测试 |

业务场景覆盖：

- 初始化后精确的表数、来源计数、用户名冲突、签名与默认无员工授权；拒绝重复初始化。
- 用户名/手机号登录、错误凭据、密码/会话字段不泄露、登录失败审计。
- 修改密码、重置密码、退出、暂停后旧令牌失效。
- 临时账号创建、编辑、暂停、恢复与角色清空；禁止通过临时账号接口修改 HR 员工。
- 用户查询筛选、分页、详情、部门树可见范围与不能越权扩大到 ALL。
- 业务角色与管理权限共用 RBAC0；无管理身份旁路；立即撤权、自我撤权与本地恢复。
- 无效角色集合替换回滚、禁用角色拒绝授予、批量部分成功和回收。
- 应用/菜单/API/角色创建及修改、关联集合读写、跨应用绑定拒绝、目录循环与 API 路径冲突。
- 部门冻结/解冻、HR 部门和员工同步、调岗清角色、离职幂等及旧会话失效。
- 部门合并迁移人员和子部门、保留角色、重复合并与循环合并拒绝。
- OA 重复授权/回收、独立应用凭据、无效服务凭据与无效操作拒绝。
- 数据库篡改失败关闭、日志筛选、健康接口。
- 可选全量来源：111 部门、10000 员工、18 来源应用、359 来源功能、10001 账号、21 总应用与恢复登录。

## 场景矩阵设计

测试按以下维度拆分，避免只由全权限初始账号验证正常流程：

| 维度 | 具体场景 | 结果验证 |
|---|---|---|
| 最小权限 | 仅用户查看、仅授权查看、仅部门查看、仅角色查看、无权限 | 分别验证部门/用户/角色目录，所有只读角色都不能写入 |
| 授权链状态 | 分别停用应用、角色、菜单、API、父菜单，再恢复 | 旧令牌立即拒绝对应业务，恢复后重新允许 |
| 关系完整性 | 菜单循环、跨应用父级、部门循环、缺失签名 | 返回 INTEGRITY_FAILURE，不能放行 |
| 多角色 | 两个独立角色的权限并集、重复保存、移除其中一个 | 只撤回被移除角色的权限，其他权限保持 |
| 账号状态 | 停用登录、只改一个字段、重复手机号、错误来源类型 | 拒绝错误操作，省略字段保持，冲突写入整笔回滚 |
| 组织变更 | 同部门调岗、跨部门同步、同步停用、离职、合并部门、重名员工 | 对比角色保留/清空、令牌失效、部门不变与用户名唯一性 |
| 资源写入 | 跨应用修改、目录绑定、非法方法、重复关联 | 错误操作回滚，重复保存无重复行 |
| 批量失败 | 普通业务拒绝、无效会话、完整性故障 | 普通拒绝报告部分结果；认证或完整性故障中止，不给后续目标授权 |
| 原子性与并发 | 无效来源导入、两个请求同时替换角色 | 无半成品导入，无混合角色集合，持久化签名仍有效 |
| 恢复 | 缺失初始角色菜单、IAM 被停用 | 正常缺失恢复；异常 IAM 状态拒绝恢复 |
| JWT 合约 | 正确签名但算法/类型/kid/关键头/字段内容错误、弱密钥、密钥不匹配 | 内容不合约返回 INVALID_TOKEN，配置故障返回 AUTH_STATE_UNAVAILABLE |
| 持久化配置 | 密钥首次生成、重启读取、文件损坏、部分显式配置、禁用自动生成 | 密钥不被静默替换，错误配置失败关闭 |
| 启动入口 | 正常启动、显式 import、显式 recover、未知模式、缺失手机号 | 只分发显式操作，导入结果写报告，普通启动不导入 |
| HTTP 合约 | 404/405/415/400、请求标识合法/非法、畸形应用代码 | 状态与错误码一致，请求标识安全透传或重建，MDC 不泄露 |

业务矩阵仍由 SimplifiedMySqlIT 继承运行，因此 H2 与 MySQL 对应相同断言。配置测试使用临时目录与独立 H2 元数据，不接触真实密钥或业务库。初始化入口测试仅模拟初始化服务的调用边界；真实导入、回滚与恢复由业务测试验证。

## 报告与限制

当前仍有 64 个分支未被 JaCoCo 记为覆盖，不能据此宣称测试穷尽：

- 资源配置剩余 14 个，包含已测拒绝路径的异常探针表现，以及仅有角色关联、没有 API 关联时的菜单类型变更等独立组合。
- 拼音工具剩余 8 个，主要是非常用字符、无拼音映射和组合数量上限。
- 权限计算剩余 7 个，包含部分前置服务已拒绝的状态，以及部门目标越界等尚未细分的路径。
- JWT 剩余 6 个，包含配置缺项的不同短路位置、单元素受众数组等；其余分散于账号、HR、哈希格式和底层辅助类。
- 部分逻辑受前置约束保护，例如 SQL count 不会返回负数；不为让报告全绿而修改生产判断或排除生产类。
- 部分 Input.fail() 拒绝场景已在 HTTP 测试中断言，但调用抛异常后的探针没有完成，仍会在报告中显示缺失。不能把所有剩余分支都归因于这种统计限制。

- 覆盖率：target/site/jacoco/index.html（统计全部生产代码，不通过排除业务类提高比例）。
- 默认测试明细：target/surefire-reports；MySQL 明细：target/failsafe-reports。
- FullImport 未启用时对应场景跳过。Docker 不可用时 MySQL 场景跳过，不能算通过。
- H2 结果验证业务规则，不代表真实 MySQL 回归、性能或前后端联调；前端测试入口不在本次后端替换范围内。
- 旧验证记录 docs/TESTING.md 中的数量与覆盖率属于历史数据，以本次生成的报告为准。
