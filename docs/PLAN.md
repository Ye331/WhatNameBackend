# 简化改造决定

本项目保留 Java 21、Spring Boot、Spring Data JPA/Hibernate、MySQL、Vue 3 和 Controller → Service → Repository 三层。

## 保留

- 标准 RBAC0：用户 → 角色 → 菜单权限 → API，多角色取并集，无角色继承、禁止权限、自动过期。
- IAM 自身也登记菜单/API，通过同一套 RBAC0 管理；没有独立管理员资格。
- 用户管理范围 ALL / DEPT_TREE，后者为本人部门及下属部门。范围不是角色继承，也不授予功能权限。
- HR 人员与组织同步、调岗、离职、合并，OA 简单授予/回收，同步批量授权。
- 密码哈希、JWT、账号会话版本、Ed25519 基础数据签名、持久操作日志。
- 全量原始数据，至少两套可执行的业务演示。

## 删除

独立管理员表、等级和任命、可授权角色清单、多来源授权、外部事件状态机、数据库服务身份、nonce、短信、密码历史、JWT 黑名单、独立登录日志、后台批量任务、日志封印、编辑版本协议、全局管理锁。

23 表缩减为 11 表，见 [数据库](contracts/04-database-design.md)。不限制为旧接口兼容；前后端一起调整。

## 明确取舍

- 拥有角色配置/分配权限的人是可信管理者，不设置委派清单；ALL 只能由已有 ALL 范围且有范围配置权限的人授予。
- 用户、部门和日志操作检查部门范围；角色和应用资源是全局定义。
- HR/OA 必须校验不同的后端服务密钥，不再实现服务请求签名。演示环境在本机运行；跨机器传输使用 HTTPS。
- OA 与手工修改同一份用户角色关系。任何回收都会移除该角色，不区分来源。
- 调岗清空全部原角色，之后手动重新分配。重复通知同一个当前部门不清空新授权。
- 无事件历史和对象版本；不识别乱序旧通知。调用方按顺序发送，错误后核对当前状态。
- 关联修改锁定一个目标对象，后保存覆盖先保存，不做旧页面冲突检测。
- 注销、密码变更、暂停和离职使账号旧会话失效；注销统一退出全部会话。
- 暂不使用缓存，保留全量数据与性能实测，取消原性能硬指标。
- 原来已接受的明文演示姓名/手机号范围继续使用；不新增加密与脱敏链路。
