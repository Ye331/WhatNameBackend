# 2. RBAC0 与平台自我管理

RBAC0 只有用户、角色、权限三层；本项目用菜单作为权限单元，每个菜单可关联多个 API。

用户甲有角色 A、B。A 允许菜单 X，B 允许菜单 Y，那么甲可以使用 X 和 Y。没有“禁止”覆盖“允许”，没有父子角色，也没有先有 A 才能有 B 的规则。

源码入口：AccessService.menus / allowed / function，ManagementInterceptor.preHandle。

## 平台也管自己

IAM 是 sys_application 中的一个应用；“用户查看”“角色维护”等是 IAM 菜单权限。管理接口同样登记在 sys_api 并关联菜单。初始管理员通过普通角色关联获得这些权限，没有 sys_admin，没有特殊用户名放行。

前端按菜单编码显示页面和按钮，后端再检查真实的菜单/API 映射。浏览器手工调用隐藏按钮对应接口也不会绕过后端。

## 数据范围

sys_user.management_scope 只有 ALL 和 DEPT_TREE。DEPT_TREE 使用本人 dept_id 作为根，包含全部后代。ALL 表示全公司。

数据范围不授予功能权限。ALL 且无用户维护权限的人不能维护用户；有用户维护权限但范围外的目标也不能操作。

角色和资源是全局定义，没有角色继承或委派清单。拥有角色配置/分配权限的人是可信管理者。只有已有 ALL 范围且具备范围配置权限的人能把别人的范围设为 ALL。

练习：解释为什么把一个普通员工的范围改成 ALL，不会使其自动成为管理员。
