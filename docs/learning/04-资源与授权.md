# 4. 资源、角色与授权

源码入口：ResourceService、GrantService、BatchService。

资源按照应用组织。目录仅导航，菜单才可授权。菜单与 API 的多对多关联不能跨应用。API 以 HTTP 方法和路径模板登记，参数名称不同但形状相同的路径视为重复。

## 配置和授予是两件事

- 配置角色菜单：决定角色能做什么，修改 sys_role_permission。
- 给用户分配角色：决定谁拥有这个角色，修改 sys_user_role。
- 配置菜单接口：决定菜单允许哪些请求，修改 sys_menu_api。

用户角色只有一份事实，不再保存手工、岗位、OA 等来源。重复授予不会重复插入，重复回收不会报“来源不存在”。

完整保存使用 roleIds/menuIds/apiIds；空数组表示清空。关联修改没有 expectedVersion，后保存覆盖先保存。

## 批量

一次最多 100 人，同步循环，每人调用 GrantService 的事务方法。一个人越界失败不撤销其他人的成功。没有任务表、任务查询或后台恢复。更多人员可以分批提交。

业务失败返回逐项原因；数据库或签名异常停止，不能假定之前的所有项都回滚，需查询当前状态。

练习：用户有 A、B 两个角色，都允许请假；回收 A 后为什么仍可请假？回收最后一个允许请假的角色后为什么立即拒绝？
