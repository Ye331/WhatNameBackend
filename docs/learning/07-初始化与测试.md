# 7. 初始化、恢复与测试

先按 backend/README.md 建立 11 表数据库，再执行全量初始化。

prepare-data.py 整理全量 Excel，InitializationService 在一个事务中导入部门、员工、来源资源、IAM 权限、两套业务演示、初始角色及账号，并生成签名。任何一步失败都回滚。

111 个部门、10,000 名员工、18 个来源应用、359 条来源功能全部保留。另增加 IAM、OA 演示、HR 演示共 21 个应用。来源功能只作为资源参考，可执行演示为 OA/HR 各四个功能。

初始管理账号通过真实角色获得 IAM 权限。误删自己权限后，在本地运行 recover，恢复受控初始化账号的管理角色、范围和密码。恢复不通过 HTTP 开放，也不自动修复篡改。

## 验证命令

backend：scripts/dev.ps1 test；完整来源导入增加 -FullImport。

frontend：npm test、npm run build、npm run format:check。

普通业务测试使用隔离 H2，MySQL 专项应使用独立容器库。测试使用独立数据库。前端测试内拦截请求只验证页面契约，不能替代真实后端验收。

重点案例：越权、越部门范围、即时撤权、临时账号暂停、调岗、离职、冻结、多角色并集、签名失败、事务回滚、两次并发完整保存、批量部分成功和本地恢复。

测试以当前业务规则为准，覆盖率以实际运行报告为准。性能记录实测值，不承诺原硬指标。
