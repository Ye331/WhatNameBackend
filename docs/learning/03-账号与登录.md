# 3. 账号、临时人员与密码

源码入口：AccountService、JwtTokenService、PasswordHasher。

账号来源：1 HR、2 临时、3 初始化。正式/外包员工从 HR 同步，有唯一工号。临时人员在同一张用户表中，没有工号，由有权限且范围覆盖目标部门的人创建。

账号状态：1 可用、2 暂停、3 离职。用户不物理删除。临时账号暂停时清空角色并使旧会话失效，恢复后需要重新分配角色。

## 登录

支持用户名密码和手机号密码。密码用现有 scrypt 哈希校验，不保存明文。JWT 带用户 ID 和 session_version，不带角色权限快照。

后续请求校验 JWT 签名、有效期、账号状态和当前 session_version。改密、重置、暂停、离职或注销会递增版本，旧令牌失效。

注销统一退出全部会话，没有 jti 黑名单。权限回收不要求退出登录，因为每次业务调用重新查询权限。

## 密码设置

不使用短信或密码历史。临时账号创建时设密码；HR 新员工接口必须传初始密码；全量导入员工写入未知随机密码，由管理页面为需要演示的员工重置。

用户修改本人密码需原密码；管理者重置目标密码需对应功能权限和部门范围。密码为 8–64 位且包含字母和数字。

练习：解释“Token 有效”为什么不等于“还拥有请假权限”。
