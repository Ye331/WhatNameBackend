# 5. HR、OA 和组织变动

源码入口：IntegrationController、ServiceKeys、OrganizationService。

HR/OA 通过后端专用密钥证明身份。密钥从配置读取，不在浏览器里，不存在独立服务身份表、请求签名或 nonce。

HR 以工号识别人、部门编码识别组织。新员工生成姓名拼音首字母账号，重名优先附加手机号后四位，仍冲突追加数字。

## 调岗

实际部门发生变化 → 清空全部原角色 → 修改部门 → 更新签名及日志 → 同一个事务提交。新部门手动授予角色。IAM 管理角色也是普通角色，同样清空。

再次通知已经所在的同一部门，不清空后来分配的新角色。

## 离职

标记离职、清空角色、递增会话版本、签名和日志同事务。账号保留，不再登录；此人过去授予其他人的角色不受影响。

## 合并与冻结

合并移动原部门直属员工和直属子部门，原部门标记合并去向，员工角色保留供人工调整。

冻结只修改部门状态。鉴权检查部门祖先链，任何祖先冻结都会拒绝业务权限，不需要逐人删除角色。解冻后原角色重新生效。

## OA

OA 只发送已批准的 GRANT 或 REVOKE，修改同一份用户角色关系。不做审批引擎，不区分授予来源。

不保存事件版本和重放结果，调用方按顺序发送，旧通知乱序不会自动识别。

练习：说明调岗重复通知与“再次真正调回原部门”有什么区别。
