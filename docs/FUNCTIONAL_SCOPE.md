# 功能范围与验收

以 [改造决定](PLAN.md) 为当前边界。

| 模块 | 当前功能 |
|---|---|
| 账号 | 用户名/手机号密码登录、本人改密、管理者重置、手动创建维护临时账号、临时账号暂停/恢复 |
| 用户角色 | 查看、完整集合保存、同步批量授予/回收；唯一事实为 sys_user_role |
| 角色 | 定义、启停、配置菜单；普通角色之间无等级 |
| 资源 | 应用、目录/菜单、API 和菜单/API 关联；跨应用关联和循环菜单拒绝 |
| 部门 | 范围内查询、冻结/解冻；HR 同步和合并 |
| HR | 工号识别人、部门编码识别组织；同步、调岗、离职、部门合并 |
| OA | 已审批的角色授予/回收，重复执行结果稳定，不运行审批流程 |
| 安全 | 密码哈希、JWT、session_version、关键对象及授权集合 Ed25519 签名、登录/管理/鉴权日志 |
| 初始化 | 全量数据、IAM 自身权限、两套业务演示、初始管理账号、本地恢复 |

## 验收步骤

1. 初始管理账号登录，查看全量员工和部门，创建一个临时账号。
2. 给用户分配演示业务角色，使用同一账号登录，调用 OA/HR 演示功能。
3. 回收角色，保留原 JWT，下一次业务请求应拒绝。
4. 具有用户查看权限而没有维护权限的用户只能读；有维护权限但目标在部门范围外仍拒绝。
5. HR 调岗清空全部原角色；重复当前部门通知不清空后来新授予的角色。
6. HR 离职清空角色、保留账号、使旧 JWT 失效。此人以前给别人分配的角色不受影响。
7. 部门冻结影响后代权限，解冻恢复原角色权限。
8. 同步批量包含合法和越界用户，分别返回成功/失败，成功项不回滚。
9. 修改数据库中的手机号或授权关联而不更新签名，鉴权应拒绝。
10. 管理员删除自己的管理角色后失去管理权限，本地 recover 可恢复初始化账号。

性能使用实际数据和测量条件记录，不承诺 20ms 或万人高峰指标。
