## D MySQL / HTTP 覆盖

1. 有效菜单并集、去重、祖先导航补全；只有实际授予菜单才能构成 API 允许。
2. B 当前允许权限菜单作为父节点：补全的父节点标记 navigationOnly，其 API 不因显示而被授予。
3. 同义模板、未知路由、错误方法和非法路径；未知路由为明确拒绝决策。
4. 未提供可信服务身份、JWT 或伪造令牌不能通过；正式默认实现不接受测试头/应用头。
5. 同一角色两条独立来源，回收一条仍允许，最后一条回收后拒绝。
6. 外层事务保留旧快照时，新鉴权仍读取已提交的回收结果。
7. 部门祖先冻结，菜单为空且 API 拒绝；账号状态保持可用，解冻按当前权限恢复。
8. 多菜单共享 API 的 OR 行为；停用其中一菜单仍可走另一个，停用祖先或移除最后映射后拒绝。
9. API、角色、应用停用以及账号暂停均不产生允许。
10. 身份字段、角色集合、角色菜单及菜单 API 成员被无签名修改/删除时拒绝；即使签名关系集合，缺少一致有效来源仍拒绝。
11. 指定 jti 注销及 session_version 变更立即使旧 JWT 失效。
12. MyBatis 测试专用拦截器注入审计写入故障：返回 AUDIT_UNAVAILABLE，不新增成功决策或返回允许；恢复后可继续正常决策。
13. 业务、身份签名和变更审计一起回滚；无调用方事务不能签名。
14. 撤权后，历史证据仍可使用留存快照与历史公钥验证；不以现时授权重建历史。
15. 调用真实 C 的管理员范围规则验证 US06 和 LG01—LG04；范围外证据隐藏，分页边界检查正确。
16. 修改封签证据后无法验签；数据库原有日志禁止更新和删除约束继续有效。

## 复现

在个人测试库完成 `db/01_schema.sql`、`db/02_add_canonical_path_and_index.sql`，从本地安全配置注入：

```text
D_DB_TEST=true
A_TEST_DB_URL=<个人 MySQL JDBC URL>
A_TEST_DB_USERNAME=<应用数据库账号>
A_TEST_DB_PASSWORD=<本地安全注入>
```

然后执行 `mvn clean verify`；仅运行 D 专项可用 `mvn -Dtest=DMySqlIntegrationTest test`。运行会增加永久保留的测试账号、来源和日志，只对可清空的个人开发库运行。本次经用户授权使用原开发库，最后核对仅有本轮 D 随机前缀数据后恢复空的当前 01+02 结构。
