# C2-04 OA Decisions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 OA01 的受控授权、审批来源去重及精确回收，与 A 事件结果和 D 签名审计原子提交。

**Architecture:** Controller 对原始请求体调用 D 服务认证接点，再解析严格 DTO。A 既有 ExternalEventService 将 OA 信任检查路由给独立 D 接点，HR 路径不变。C 取得统一业务锁，锁并验签既有服务身份配置，按当前角色/部门/操作范围修改来源和有效关系，复用 GrantMapper/GrantState/D 完整性与审计。

**Tech Stack:** Java 21、Spring Boot、MyBatis、MySQL 8.0.46/Testcontainers、JUnit 5。

**Spec:** [总计划第六节](2026-10-18-c-stage2.md)、[交接](../../C_STAGE2_HANDOFF.md)、`docs/contracts/02-api-spec.md` OA01/2.4、`03-openapi.yaml` OA01、现有 sys_service_identity / sys_user_role_source。

## Global Constraints

- 不新增事件框架、认领字段、在线接管、数据库表/字段或对外契约字段。
- 原申请人当前任命不参与服务执行资格；不伪造管理员，不复用人工回收。
- 保留 C2-01～03 全部未提交改动和证据；不并发运行 Maven，不自动提交/推送。
- D 服务认证缺失时生产默认拒绝；测试替身只替换服务请求认证，不替代配置范围、D 规范数据签名或真实数据库事务。
- 业务事实、grant_revision、两份用户签名、关键审计与 APPLIED 同事务；缺签不补签，撤销来源不自动恢复。
