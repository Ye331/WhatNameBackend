# C2-06 Grant History Implementation Plan

> Execute task-by-task in this session, as requested by the user. Preserve C2-01–05 and their evidence. Do not start parallel agents or change the shared contracts.

**Goal:** Implement GR04 as verified source-level historical changes, with current target scope and pagination after expansion/filtering.

**Architecture:** C reads candidate operation-log rows in bounded ID pages, delegates seal/metadata verification to D in the same read transaction, and projects changes from sealed before/after source snapshots. Current C M5 facts determine target visibility; current sources, roles, appointments of the historical author and batch results never supply historical facts. Keep only one response page in memory while counting the complete verified result.

**Tech Stack:** Java 21, Spring Boot, MyBatis, MySQL, Maven Wrapper, JUnit/Testcontainers.

**Spec:** [Stage plan C2-06](2026-10-18-c-stage2.md), [handoff](../../C_STAGE2_HANDOFF.md), API GR04 and OpenAPI `/grants/history`.

## Global Constraints

- 使用既有三层架构，不增加 DAO、Redis、内部 HTTP 接口或第二套事件框架。
- 对外 ID 继续使用十进制字符串，保留既有字段、错误码及版本语义。
- 不改写历史授权来满足现时规则，不自动恢复已撤销来源，不因验签失败给旧数据自动补签。
- GR04 exposes exactly eventId/userId/roleId/grantSourceId/operation/occurredAt; actor, reason and batch links remain in D's sealed evidence. No response extensions or migrations.
- OpenAPI also lists optional from/to; accept zoned timestamps and inclusive instant bounds, plus user/role filters and page 1..1000000, size 1..500.
- Unsupported/unsealed visible grant audit records fail INTEGRITY_FAILURE. A source without a historical audit creates no invented event. Document both legacy limits.
