## 减少冗余的具体做法

1. `IdUtils.parse` 是 ID 文本校验的单一实现。业务类直接使用它，删除六处原有方法，历史查询仅保留“可选参数为 null”的转换。
2. 管理范围集合由 `AdminPolicyService.managedScope` 计算。`AManagementPolicy` 只保留账号模块所需的加锁和错误码适配，不再依赖另一份组织 Mapper、签名服务和链遍历。
3. 部门树索引每次查询建立一次；不在每个节点的循环内重复建立。
4. 三个自定义弹窗共用 `dialogKeys`。每个调用方仍自行决定忙碌时能否关闭，没有引入弹窗框架。
5. 正式前端使用统一排版；保留简单 Vue 组件、现有请求封装和列表方法。行数增加是因为展开原来的单行模板，不是增加业务功能。
6. 不为每个 Service 新建接口/实现类；现有跨模块签名和审计适配仍承载事实转换及事务职责，不按类名或行数机械删除。

## 有意保留的复杂度与限制

- 签名、可信审计、授权来源、事件幂等、批量恢复和事务一致性来自详细设计。删除这些不是等价重构。
- 当前管理写入采用较宽的固定加锁顺序，部分账号查询也复用该协议。这是并发正确性与性能的现有取舍；本轮没有未经并发验证便删锁或改成缓存。
- 历史查询为精确总数逐批验签、过滤候选记录，前端多选历史还会读取多页。可进一步优化查询投影，但涉及留存证据与范围语义，不能简单改成“只验当前页”来提速。
- 演示初始化、超级用户恢复、真实部署与正式性能指标不在本轮已完成范围。
